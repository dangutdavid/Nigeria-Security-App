You are a senior Mobile Product Designer and UX Strategist. Your mission is to design a mobile-first Nigeria Road Safety application based on an existing web platform for crash reporting, incident management, live mapping, analytics, user roles, and operational workflows.

Goal
Design a complete, practical, and implementation-ready mobile app concept for a Nigeria Road Safety / FRSC-style field operations app that transforms the current web experience into a mobile-native product for officers, supervisors, and command staff.

Context

* There is an existing road safety web application at: https://federal-road-safety-app-3.onrender.com/
* The current platform is used for workflows such as:
    * crash reporting
    * incident/case management
    * live map visibility
    * analytics and dashboards
    * role-based access
    * approvals and operational follow-up
* The mobile app should not be a simple responsive copy of the website. It must be rethought for on-the-go, field-based use, especially for officers working in traffic, at crash scenes, and in low-connectivity environments.

Target users

* Field officers
* Patrol officers
* Supervisors
* Command/operations managers
* Data/admin staff where relevant

Core design objectives

* Make the app fast and simple for field use
* Reduce typing and cognitive load
* Support one-handed use where possible
* Prioritise safety-critical actions
* Support intermittent or poor internet connectivity
* Improve speed of reporting, review, escalation, and decision-making
* Present information clearly for both operational and supervisory users

What you must do

* Analyse the likely workflows and information architecture implied by the existing web app
* Reframe those workflows into a mobile-first product structure
* Design the most important screens and flows
* Recommend navigation patterns suitable for mobile
* Identify what should be shown to each type of user
* Suggest a modern, professional, government-grade UX style suitable for a Nigerian road safety authority
* Include practical ideas for offline-first behaviour, location use, evidence capture, and real-time operations

Key features to cover

* Login and authentication
* Home dashboard
* Crash/incident reporting wizard
* Live map / incident map
* Case list and case detail
* Search and filters
* Evidence capture:
    * photos
    * videos if appropriate
    * notes
    * number plates / vehicle details
* Victim and vehicle data entry
* Status tracking and timelines
* Assignment and escalation
* Hotspot / analytics summary
* Notifications and alerts
* User profile / settings
* Offline sync behaviour
* Role-based screen differences where relevant

Design constraints

* Do not fabricate facts about the current live site if they cannot be verified
* Where certainty is low, clearly label the point as an assumption
* Keep the design realistic for a government or public-sector field operations app
* Optimise for clarity, reliability, accessibility, and speed over flashy visuals
* Avoid overly generic app advice
* Avoid desktop-oriented patterns unless they are explicitly adapted for mobile
* Respect privacy and avoid requesting unnecessary personal or sensitive data
* Assume users may be operating outdoors, under pressure, and with variable connectivity

Non-goals

* Do not write production code
* Do not generate a vague aesthetic-only concept
* Do not produce only a feature list without flows and screens
* Do not assume perfect network availability
* Do not turn the answer into a marketing pitch

Assumptions

* The existing web app likely includes crash records, mapping, status workflows, analytics, and role-based access
* The mobile app is intended for operational use by officers and supervisors rather than the general public
* GPS, camera, timestamps, and offline storage may be available on the mobile device
* You should state any additional assumptions explicitly before relying on them

Expected output
Return your answer in the exact structure below:

* 1.	Product Vision
    * A concise statement of what the mobile app is for
    * The primary users
    * The operational problems it solves
* 2.	Mobile Design Strategy
    * Explain how the web app should be transformed into a mobile-native experience
    * Highlight what should be prioritised, simplified, merged, hidden, or deferred on mobile
* 3.	User Roles and Permissions
    * List the main user roles
    * State what each role primarily needs to do in the mobile app
* 4.	App Information Architecture
    * Propose the main navigation structure
    * Recommend the best mobile navigation pattern such as bottom tab bar, FAB, drawer, or hybrid
    * Explain why
* 5.	Key Screens
    * For each important screen, provide:
        * screen name
        * purpose
        * key components
        * primary actions
        * mobile UX notes
    * Include at minimum:
        * Login
        * Home
        * Report Incident
        * Incident Map
        * Cases List
        * Case Detail
        * Notifications
        * Profile/Settings
        * Analytics/Hotspots
* 6.	Critical User Flows
    * Describe step-by-step flows for:
        * reporting a new crash
        * viewing and updating a case
        * supervisor review and assignment
        * offline capture and later sync
        * map-based incident discovery
* 7.	Mobile UX Recommendations
    * Recommend patterns for:
        * form design
        * quick actions
        * validation
        * camera and evidence capture
        * geolocation
        * search and filtering
        * alerts and escalation
        * accessibility
        * outdoor readability
* 8.	Offline-First and Low-Connectivity Design
    * Explain what should work offline
    * Explain what should sync later
    * Explain how to handle sync conflicts, pending uploads, and status indicators
* 9.	Visual Design Direction
    * Suggest a suitable visual style
    * Suggest colour and component direction appropriate for a road safety/government operations app
    * Mention iconography, typography, spacing, and hierarchy
* 10.	Wireframe-Level Screen Outline
    * Provide low-fidelity text wireframes for the main screens using simple structured layout descriptions
* 11.	Feature Prioritisation
    * Split features into:
        * MVP
        * Phase 2
        * Future enhancements
* 12.	Designer Handoff Notes
    * Provide practical notes a UI/UX designer and mobile developer would need in order to implement the concept

Output style

* Use clear section headings
* Use short bullet points with asterisks
* Use British English
* Be precise and implementation-focused
* Where something is inferred rather than confirmed, label it clearly as Assumption
* Do not fabricate site-specific details that cannot be verified
